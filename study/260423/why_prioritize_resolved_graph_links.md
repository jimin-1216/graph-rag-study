# Why Prioritize Resolved Graph Links

작성일: 2026-04-23

## 질문

왜 검색 파이프라인에서 문자열 alias 매칭보다 `REFERS_TO_DOCUMENT` 같은 해소된 그래프 관계를 우선 써야 하는가?

## 짧은 답

질의 시점의 추측을 줄이고, 전처리 단계에서 이미 해소한 관계를 재사용할 수 있기 때문이다.

## 기존 방식

기존 상위법 확장은 사실상 아래 흐름에 가까웠다.

```text
질의
-> 내부문서 후보 검색
-> 조문 안의 법령명 문자열 추출
-> 문자열 유사도/포함 여부로 법령 제목 재매칭
-> 상위법 후보 추정
```

문제:

- 같은 alias를 질의할 때마다 다시 해석해야 한다.
- 띄어쓰기 깨짐, 약칭, 시행령/법률 구분에 흔들린다.
- Graph RAG처럼 보여도 실제로는 텍스트 후처리 비중이 크다.

## 개선 방식

alias 해소 파이프라인 이후에는 아래 흐름이 가능하다.

```text
질의
-> 내부문서 후보 검색
-> 관련 조문 조회
-> 조문에 연결된 REFERS_TO_DOCUMENT 사용
-> 상위 법령 확장
```

즉 질의 시점에는 이미 만들어진 그래프 관계를 조회만 하면 된다.

## 좋아지는 점

### 1. 정확도 상승

- 예전: `특정금융정보법` 같은 문자열을 매번 다시 제목에 붙여야 했다.
- 지금: `internal unit -> LegalDocument`가 이미 연결되어 있다.
- 결과적으로 상위법 확장이 더 안정적이다.

### 2. 검색 결과 흔들림 감소

- 동일 질의 반복 시 결과가 덜 흔들린다.
- 띄어쓰기 오류, 법령명 변형, 줄바꿈 깨짐 영향이 줄어든다.

### 3. 질의 시 파이프라인 단순화

- alias 후보 생성, 점수화, best-match 선택을 매 질의마다 반복하지 않아도 된다.
- 무거운 해소 로직은 오프라인 전처리로 밀고, 질의 시에는 그래프 탐색만 수행하면 된다.

### 4. Graph RAG다운 구조가 된다

- 텍스트 검색은 후보 조문을 찾는다.
- 그래프는 확정된 문서 관계를 따라 상위법과 연결한다.
- 역할 분리가 선명해진다.

## 예시

질문:

`보고책임자의 역할은 무엇인가`

기존:

- `보고책임자`가 있는 조문을 찾는다.
- 그 조문 안의 법령명을 다시 문자열로 매칭한다.
- 매칭 실패 시 상위법 확장이 비거나 흔들린다.

개선:

- `보고책임자` 관련 조문을 찾는다.
- 해당 조문의 `REFERS_TO_DOCUMENT`를 바로 따라간다.
- 상위법 근거 문서까지 확장한 뒤 컨텍스트를 조립한다.

## 현재 판단

`REFERS_TO_DOCUMENT` 우선 사용은 단순 최적화가 아니라, 검색-그래프 탐색 파이프라인을 텍스트 추정형에서 그래프 재사용형으로 바꾸는 전환점이다.
